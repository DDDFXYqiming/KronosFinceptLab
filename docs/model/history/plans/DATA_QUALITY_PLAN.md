## 一、数据源能力验证

### A 股（通过 `fetch_a_stock_ohlcv()`，多源回退：EastMoney → BaoStock → Yahoo）

| 时间跨度 | 数据行数/股 | 覆盖率 |
|---------|-----------|--------|
| 2010-01 ~ 2026-07（当前） | **~4000 行** | 老股（2000年前上市）全覆盖 |
| 2010 年后上市（如宁德时代、药明康德） | ~1450~2000 行 | 按 IPO 时间 |
| 2022-01 ~ 2026-07（当前训练） | ~1100 行 | 全部 |

**实测 40 只沪深 300 成分股从 2010-01-04 均可拉取**，最早的 2010-01-04，最晚 4019 行。新上市股票（688xxx 科创板、部分 2018 后 IPO）行数较少，按实际 IPO 日期。

### 港股（通过 yfinance）

| 时间跨度 | 数据行数/股 | 覆盖率 |
|---------|-----------|--------|
| 2010-01 ~ 2026-07 | **~4078 行** | 老牌恒指成分股全覆盖 |
| 新上市（阿里 2019、美团 2018） | ~1600~1900 行 | 按 IPO 时间 |

**实测 15 只恒指成分股 14 只 OK**，唯一失败的 0011.HK（恒生银行）可能是代码格式问题。

## 二、改进方案（按收益递减排序）

### Step 1: 扩展时间范围（最大收益，零成本）

**改动**：将数据下载起始时间从 `20220101` 改为 `20100101`

**收益**：每只股票从 ~1100 行 → ~4000 行，数据量 **3.6x**

**工作量**：
- 修改 `download_all_data.py` 中的 `START = "20100101"`
- 新增文件清理和重新下载（~2 小时，300+85 只）
- 重新微调（~3.5 小时）
- 总估计：~6 小时

**风险**：无。API 已验证可用，代码已支持任意时间范围。

### Step 2: 市值过滤（精选成分股）

**改动**：在沪深 300 内按市值筛选 Top 150

**数据来源**：AKShare `stock_individual_info_em` 或 `stock_zh_a_spot_em` 可获取实时市值
```python
import akshare as ak
df = ak.stock_zh_a_spot_em()  # 全A股实时行情，包含市值
df_filtered = df[df['流通市值'].astype(float) > 500e8]  # 例：>500亿
```

**收益**：剔除低流动性、高噪声的小市值股，方向准确率预估 +0.5~1%

**工作量**：
- 新增市值过滤脚本（~30 分钟）
- 过滤后约 150 只 A 股 + 85 港股 = 235 只
- 重新微调更快（数据量减少）
- 但注意：时间扩展到 2010 后总数据量仍比当前大

**风险**：市值是动态变化的。固定某个时间点的市值做过滤可能导致幸存者偏差。

**建议**：用**当前市值**做静态过滤，或使用中证指数公司发布的权重排名。

### Step 3: 异常值清洗

**改动**：在 `CustomKlineDataset._preprocess_df()` 中添加清洗逻辑

**可实现的清洗**：
```
1. 剔除日收益率绝对值 > 20% 的行（数据错误/极端事件）
2. 剔除训练期内数据 < 200 行的标的（IPO 太短）
3. Forward fill 缺失值（已有）
4. 剔除连续相同价格超过 5 天的窗口（停牌）
```

**收益**：减小训练噪声，预估 +0.3~0.5%

**工作量**：
- 修改 `_load_multi_stock` 中的过滤逻辑（~15 分钟）

## 三、推荐执行路径

```
Phase 1: 扩展时间范围（高收益，低风险）          ≈ 6 小时
  ├── 修改 download_all_data.py: START→20100101
  ├── 重新下载全部 385 只股票 CSV
  ├── 重新微调 Kronos-small
  └── 验证对比

Phase 2: 质量过滤（中等收益，低风险）             ≈ 2 小时
  ├── 实现市值过滤脚本
  ├── 新增异常值清洗逻辑
  └── 重新微调 + 验证

Phase 3: 仅当 Phase 1+2 成功后
  └── 尝试 Kronos-base 微调（预估 4x 训练时间）
```
